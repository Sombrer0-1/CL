## 1. 目标与时间

验证 Orion 在代表场景中是否产生有用的学习质量—时间—内存权衡，查明收益与局限，为后续研究提供依据。不预设正向结论，不追求逐图逐表或原设备数值复刻。

目标总工作量约 24 小时以内；这是估算，不是硬截止。不会因时间到限终止正常训练。通过减少组合、复用合格结果和优先解决核心问题来控制成本。新的运行矩阵预计约 4–15 小时串行训练，另预留 2–5 小时验证和分析；首次运行后按实际墙时更新。性能异常或修复可能使预估失效，需说明，不偷偷减数据或 seed。

## 2. 保留与不再扩展的范围

- 保留全量约定训练划分、完整 experiences、单遍新数据、ResNet-20、URGE 式 (1)–(5)、真实 replay、原始指标矩阵及资源轨迹。
- 新主实验集中于 SplitCIFAR100（10 experiences）和 CORe50-NC（9 experiences），ER 为基底，seeds 0/1/2。
- 已有 71 次正式运行及开发结果保留为历史背景；不同源码/协议结果不直接合并成新比较。历史 GSS 崩塌、预取变慢、MAX-A 弱结果不能删除。
- 不再补齐 MAX-A 全数据集矩阵、8×42 Oracle、非 ER 的所有新组合、Endless 144 格。它们是本轮范围外，不是完成或资源失败。
- 本轮不开发 host cgroup 硬限制、全成本模型、全算法 checkpoint 恢复、动态轨迹预取回放。已有代码能力保留，未验收能力不宣称可用。
- Jetson 能耗、原设备耗时、机器人闭环仍为平台外。

## 3. 唯一活动矩阵

配置在 `configs/light24/`，矩阵在 `experiments/light24/`，生成器 `orion_repro.light24`。全局 study_id=light24_v1，旧 E 编号改由下列 L 阶段承接。

| 阶段 | 范围 | 次数 | 训练估算（小时） |
|---|---|---:|---:|
| core | 两场景 × 静态 ER/仅 batch-replay 自适应/完整 Orion × 3 seeds | 18 | 0.5–2 |
| search | 两场景 × batch {16,64,256} × replay {200,2000}，开发 seed0 | 12 | 0.5–2 |
| selected | 每场景开发选出的静态配置 × 3 seeds，正式评价 | 6 | 0.25–1 |
| budget | CIFAR100 × 静态 ER/Orion × {128,256,512} MiB allocator 配额 × 3 seeds | 18 | 0.5–2 |
| preference | CORe50-NC × latency/P-S 两偏好 × 3 seeds；balanced 复用 core | 6 | 0.25–1 |
| prefetch | CORe50-NC 静态 ER 固定配置 × on/off × 3 seeds | 6 | 0.25–1 |
| sensitivity | 两场景 × Thr0 {0.025,0.1} × 3 seeds；主值 0.05 复用 core | 12 | 0.5–2 |
| endless | IC/IL/WC × 静态 ER/Orion × 3 seeds | 18 | 1–4 |
| 合计 | 90 个预生成配置 + 搜索后生成 6 个 | 96 | 约 4–15 |

估时为历史同类运行加余量，非逐格实测承诺。core 的历史正式运行约每次几十秒至数分钟，MAX-A 小 batch 长尾已移出。遇到异常先核实加载、算法和资源；如有科学必要，可超过估算完成正常运行。

推荐顺序：core → search → selected → budget → preference → prefetch → sensitivity → endless → 汇总分析。不得依据正式结果好坏决定保留哪些 seed。若两种自适应在某场景实际行为完全相同，如实报告消融未产生干预，不改参数追求差异。

## 4. 冻结协议与公平性

详细协议见 `docs/protocols/light24_v1.md`；算法、数据和测量定义见 `docs/METHODS.md`、`docs/protocols/metric_definitions.md`，公式以本地 PDF 为准。

- 正式主比较沿用 paper-feedback 口径：官方训练划分 + 已见官方测试反馈。它是论文口径重建，不是独立无测试反馈的泛化评价；不利用这些结果选参。
- search 仅使用开发 val：按 (P_diag+S_initial)/2 最大选择，平局选 online_total_s 更短，再按配置路径字典序。候选必须完整得到可信 outcome；实现错误先修。当前自动选择器要求 12 格全部 completed；资源不可行需明确记录并先修订选择验收，不静默跳格。有限搜索不命名为完整 Oracle。
- sensitivity 是预先确定的敏感性展示，不回填主配置；本轮只扫描阈值，其他未给定参数仍列局限。
- budget 使用 PyTorch allocator 限额，单独记录 allocated/reserved、RAM 与失败。它不约束驱动/其他进程/全部系统显存，不称 Jetson 共享内存模拟。不把软件 allocator 实验写成全内存保证。
- prefetch 使用静态 batch/replay/插件轨迹，on/off 仅 enabled 不同，确定性算法开启，CUBLAS 配置由执行器设置；计时仅在这组内部配对，不能与非确定性 core 耗时混算。小型等价性探针 + 全流评价/访问计数共同验收，不宣称所有动态策略预取已验证。
- Endless 保留 grouped_v2 的完整开发训练流和固定 val（split seed17），种子改变模型/采样不改变划分。三 seed 仍属于辅助开发划分结果，不混入官方测试主表。数字 patch ID 非真实时间戳，不能宣称彻底消除了时间泄漏。

## 5. 执行与追溯

`orion_repro.study` 默认自动复用 identity 匹配的 completed；保留资源失败，遇到实现错误暂停。每次执行独立子进程，日志及配置在 runs；累计实际执行时间在 `runs/light24_progress.json`。Ctrl-C/SIGTERM 只终止本执行器创建的子进程组并保留中断记录。没有时间杀进程规则。

v2 identity 包含本项目 Python 源码、pyproject、实际配置、依赖锁和数据 manifest，忽略无关配置/文档/矩阵变化；旧 v1 仍可读但不强行转换。源码改变会使新旧身份不同：修复后重跑受影响的配对组，禁止仅按名字或 seed 混合结果。每个 run 仍保存完整来源快照。

唯一运行状态是 STATUS + study_report 的当前 identity 覆盖表；文件存在不表示进程活着。源码更新、选参和数据准备时不要并行训练。旧矩阵仅保留为参考，不要恢复。

## 6. 验收与交付

1. 当前代码关键测试通过；小型真实训练验证新增消融生效、提议/实际轨迹区分正确。
2. 96 个格子有完整结果或有证据的资源失败；未执行、实现错误和用户中断不算完成。预计耗时不是强制验收条件。
3. 主要比较 3 seeds，报告均值、样本标准差、配对差及失败数；不给未完成格填零。开发搜索与正式评价分表。
4. 交付主对照/Pareto、控制轨迹、预算成功率与峰值、偏好与阈值敏感性、预取时间/等待/额外内存、Endless 辅助表、开销分解。
5. C01–C08 逐项标记支持/部分支持/不支持/未验证，并注明本轮只覆盖代表性子命题。C04 新算法全覆盖已移出，历史结果只能作为限定证据。不能把本轮完成写成原全计划完成。
6. 结果解释围绕“是否比可信静态配置有益、收益来自哪里、哪些条件失效、下一步研究机会”，不以符合论文数值为目标。
