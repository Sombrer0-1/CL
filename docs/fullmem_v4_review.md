日期：2026-09-20。依据：用户要求核对四项重点、查漏并成熟化PLAN。本次仅修订设计，不修改训练实现、不启动实验、不变更系统。

结论：四项重点方向完整，原稿缺少若干可执行规则；已在根PLAN及规范附件fullmem_v4_design.md补齐。设计v1可以作为后续实现与校准依据，但不能视为G1/G2已完成或参数已冻结。

| 原稿缺口/冲突 | design-v1处理 |
|---|---|
| 紧/中/宽预算只说校准，没有选择规则 | 基础静态可行性与预注册资源剖析选档，三档不存在时保留缺口，不复制或保证Orion成功 |
| 真共享池只作原则描述 | 交叉分配/释放、重复检查、物理余量与容量变化验收；未通过不能软件替代 |
| 背景/缓存/热漂移与agent干扰 | 远程runtime、空载窗口、固定服务/预热政策、预算块锚点、污染与补跑规则 |
| 内存反馈和硬预算混淆 | 定义MemTotal与训练峰值占用估计，声明重建假设，物理执行和观测分层 |
| 原式未必及时触发收缩 | 显式诊断内存sigmoid饱和、边界反馈滞后，安全阈值不能偷偷加入主方法 |
| 物理映射/插件释放未覆盖过渡 | 区分输入字节、激活、workspace与M_O，记录连续余量、重配置共存峰值和释放滞后 |
| buffer扩容与latent replay语义 | 区分容量/批次/filled/owned，不复活已丢样本，LR保持方法差异 |
| H4–H8尚无明确设计 | 明确序列、组件全因子、插件拆分/始终开、偏好/衰减、预取、15种敏感性；总名额1320去重前 |
| 预取收益与控制器收益混杂 | 主比较共用预取底座，静态等价配对，在线Orion交互和冻结轨迹诊断分名 |
| 反馈变体训练量可能不同 | validation/paper-feedback使用同一训练子集配对，开发与测试选择边界显式化 |
| 全方法可行才准入会删除OOM问题 | 基础评估可行性用于预算准入，其它方法失败作为正式结果保留 |
| 系统服务独立不等于注销存活 | 增加linger/服务生命周期验证、幂等提交、断线/重启/盘满等专属故障检查 |
| 整机OOM与失联取证不足 | 状态机与原因分离，监督器保护单列，重启后健康检查，未知不强判OOM |
| 缺项阻断范围含糊 | 阻断对应无效块和“完整”称号，允许其它已验收独立块执行 |
