# fullmem_v4 远程运行与detach契约

日期：2026-09-20，design-v1操作补充。本文是 [PLAN](../PLAN.md) 和 [详细设计](fullmem_v4_design.md) 的规范性组成部分。**当前只是设计，独立队列执行器与detach验收尚未实现。**

## 1. 角色与生命周期

agent在控制机上准备任务、审阅异常、分析结果；Thor上的轻量队列执行器负责按已冻结规则启动/记录/回收实验。训练过程中的URGE由实验代码自行执行，不调用外部agent。资源采样、健康检查和终态落盘由普通程序承担，不需要agent持续推理或轮询。

允许agent提交后detach，关闭SSH甚至退出控制机上的agent runtime。Thor的执行器和worker由独立systemd服务管理，与SSH会话、shell和控制机存活解耦。没有活动SSH连接时仍可执行整个已准入批次，不仅仅维持当前一个训练进程。

用户服务方案必须验证退出最后一个登录会话后仍存活；如需linger/系统级服务，应在部署时完成相应授权配置。不能把nohup、tmux或一条后台命令本身当作持久队列与恢复已经实现。

## 2. detach前的交接清单

仅允许提交已通过对应门槛、所有字段均已赋值的批次。保存batch ID、任务manifest、源码/数据/环境/启动预算哈希、确切顺序、每格输出目录、资源锁、失败继续政策和日志空间要求。开发探针可单独组成有界批次，不冒充冻结正式队列。

detach前确认：服务已启动且状态已持久化；执行器不依赖当前终端环境；远端磁盘足够；独立记录器有效；没有等待密码/交互输入；用户知道如何查询状态。agent在交接回复中给出batch ID、状态文件/日志路径、预计耗时和暂停条件。预计耗时不是自动终止正常训练的截止时间。

同一无人值守批次默认只含**一个已验收启动容量**，不自动修改启动文件、不自动升级环境、不跨预算重启。需要切换容量或恢复整机时暂停等待接管；未来如要自动重启必须另行设计并验收回退与授权范围。

## 3. 自动推进与暂停边界

| 事件 | 执行器行为 |
|---|---|
| 实验完成，证据齐全，健康/背景复查通过 | 自动启动manifest中的下一格 |
| 已预期的局部CUDA/host OOM，退出证据齐全 | 保存失败；确认整棵worker进程树退出、资源回收、背景有效后，按冻结政策继续下一格；不原地重试 |
| SSH断开、控制机关闭或agent退出 | 按原队列继续，无需重连才能推进 |
| 背景超准入范围但无系统故障 | 延迟新任务并记录；等待窗口耗尽后暂停批次，不强杀正常训练 |
| 实现异常、配置/身份不符、数据损坏、磁盘空间不足或证据不全 | 暂停发射，保存诊断，等待agent处理 |
| 后台压力进程失效、整机OOM、未知失联、主机意外重启 | 标记异常/未知，禁止盲目续发；重连接管并健康验收 |
| 到达批次末尾 | 落盘最终清单和校验信息，进入finished，无需agent持续等待 |
| 达到预算切换点或需要修改协议 | 进入awaiting_intervention，不自主更改实验设计 |

每次继续前的资源回收/背景检查是必要条件，不仅以worker exit code决定。健康阈值和等待窗口在G2冻结；单次正常训练不因超过时间估计被杀。卡死判定必须基于预注册心跳/进度诊断，不以“agent一段时间未收到消息”认定。

执行器自身退出后，systemd可重启监督进程，但监督进程先核对持久状态、存活worker及锁，不自动重跑训练。全局故障后的批次恢复默认paused。任务失败的自动重试默认关闭；补跑需有独立attempt和已登记规则。

## 4. 状态、备份与重连接管

本地持久状态至少包含batch ID、manifest哈希、boot ID、服务/worker身份、当前run、最后完成experience、心跳时间、完成/失败计数、暂停原因和下一任务。状态原子替换，事件追加；使用单调时钟测时长，同时保存UTC用于跨机对应。队列和关键日志位于持久磁盘，不仅在内存或临时目录。

控制机可用固定轻量程序同步小型状态/已关闭日志，不需要agent运行。控制机关闭或网络中断时Thor继续本地保存；同步恢复后校验补传。未同步区间没有远端备份保障，不能宣称远端实时留证；磁盘容量不足时禁止再发任务。无需为detach而把大日志持续刷到SSH终端。

agent重连顺序：读取manifest/状态→核对boot ID和实际服务/进程→回收尚未同步证据→核对失败及背景→决定继续既有批次或提交新批次。相同ID重复提交必须幂等，不能仅因没有SSH进程就重启训练。

无人值守不等于机器不会故障。全局内存耗尽可能影响systemd、SSH与记录器；仍需PLAN规定的现场/串口恢复途径。协议以保留已落盘证据和停止误续跑为目标，不承诺软件监督器能保证整机永不失联。

## 5. detach准入验收

使用独立小探针批次至少验证：提交两项任务后断开SSH，第一项结束后第二项自动启动；退出控制机agent不影响执行；全部结束后可取回完整终态；重复提交不重复运行；局部OOM后按政策继续；实现异常暂停；监督器重启不重复worker；目标主机重启后暂停并保留未完成attempt。

还须实际验证退出用户登录会话的服务存活、日志空间检查和断网后补传。验收通过后才允许正式批次无人值守；不能仅因为systemd-run能启动一次进程就标记通过。当前验收结果以 [STATUS](../STATUS.md) 为准。
