# A27 本机环境适配（Jetson AGX Thor）

日期：2026-09-16。分类：适配本平台。不改写 A01 在 WSL/5060 Ti、A24 在 Linux RTX 5090 上已验证的当时版本选择。不迁移 5090 的 Q/L/S*。

## 决定

- Conda：在用户目录安装 Miniconda `~/miniconda3`（aarch64）。独立环境 `orion` 位于 `/home/zhuzetong/miniconda3/envs/orion`。不向 base 装包，不使用 mineru。
- Python：3.11.16，与第一阶段起点及 A24 一致。官方 cu132 aarch64 轮子同时提供 cp311。
- PyTorch：`torch==2.14.0+cu132`、`torchvision==0.29.0+cu132`，索引 `https://download.pytorch.org/whl/cu132`。不要安装 5090 的 `cu128` 轮子，也不要 `pip install -r` 旧宿主锁文件。
- Avalanche：仍为 `avalanche-lib==0.6.0`，`--no-deps` 安装后再单独安装 `wandb==0.30.0`（带依赖；不可与 `--no-deps` 写在同一条 pip 命令里）。运行时 `WANDB_MODE=disabled`。GSS `mem_strength` 转 int 补丁保留。
- envcheck：要求 wheel 覆盖**本机设备**计算能力（Thor 为 11.0 / `sm_110`），不再把其它卡的 arch 当作本机硬条件。

## 理由

本机为 NVIDIA Jetson AGX Thor Developer Kit：aarch64，JetPack 7.2.1，L4T R39.2.1，Ubuntu 24.04.4，驱动 595.78，系统 CUDA 13.2，单卡。`nvidia-smi` 不报告独立 VRAM（`[N/A]`）；`torch.cuda.get_device_properties(0).total_memory` 约为 122 GiB 统一内存。cu132 aarch64 轮子的 `arch_list` 含 `sm_110`。系统已有驱动与 Toolkit，未重装。

Thor 属于论文的 on-device / Jetson 设备类，但不是作者未公开的原实验 SKU，也不能把本机结果写成原设备能耗或机器人闭环复现。allocator 配额仍是进程内 PyTorch 分配器分数，不是 cgroup 硬限额。

## 验证

`WANDB_MODE=disabled /home/zhuzetong/miniconda3/envs/orion/bin/python -m orion_repro.envcheck`：前向/反向/参数更新通过；设备 `NVIDIA Thor`，capability `(11, 0)`，wheel 含 `sm_110`，`memory_model=unified`。同解释器 `pytest tests` 158 passed。产物：`reports/envcheck.json`、本机 `requirements.lock.txt` / `environment.lock.yml`，归档于 `docs/environments/jetson_agx_thor/`。

## 影响

新阶段身份依赖本机锁文件。A24 / `docs/environments/linux_rtx5090/` 与 WSL cu130 锁只作离机快照。effectiveness_v3 须从 G2 重新校准；5090 的 32 GiB 离散显存配额不能当作 Thor 统一内存预算。
