# A26 换机：放弃 RTX 5090 上的 effectiveness_v3 执行证据

日期：2026-09-16。分类：适配本平台。不修改第一、二阶段采用值与结果。

## 决定

用户将转移项目到新环境。第三阶段保留可迁移的研究设计与实现，不保留本机 Linux + 双 RTX 5090 上的开发校准、冻结协议和正式跑数。

保留：

- [PLAN](../../PLAN.md)、[SDD](../SDD_effectiveness_v3.md)、[design.yaml](../../experiments/effectiveness_v3/design.yaml)
- 对齐表、验收表、A25 设计记录
- `src/orion_repro/stages/effectiveness_v3/` 及 G0/G1 测试、B01–B06 运行时修补

放弃、不得带到新机当证据：

- `configs/effectiveness_v3/<revision>/` 已生成配置
- `experiments/effectiveness_v3/revisions/` 冻结协议与 probe 清单
- `runs/effectiveness_v3*` 原始运行
- 本机写入 `experiments/registry.jsonl` 的 effectiveness_v3 行
- 任何 Q_tight / L_cal / S* / frozen_hash 数值

## 理由

预算、延迟目标和静态选择依赖宿主 GPU、allocator 与计时。换机后必须按 PLAN §5 在新宿主重新开发校准再冻结。5090 上 G4 未完成，也不应与新宿主结果混为同一矩阵。

## 换机后

1. 按新宿主重建独立 `orion` 环境并重写锁文件；A24 与 `docs/environments/linux_rtx5090/` 只是离机快照。
2. 允许按新硬件对 PLAN/SDD 做小幅平台适配，并记入新决策；不得为让 Orion 胜出而改规则。
3. 从 G2 重新校准；G0/G1 先在新宿主重跑测试与 envcheck。
4. 不续跑、不复用本机 r1 冻结。新冻结是新 revision 身份，即使仍命名 `r1`。
