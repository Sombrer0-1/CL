# CORe50 划分、输入尺寸与共享测试 P/S（A14）

论文 Table 2：NI/NC/NIC 为 8/9/79 experiences，图像总数 164866，输入 32×32。官方 CORe50 原图为 128×128；Avalanche `mini=True` 使用 `core50_32x32.zip`。本仓库只下载 mini，不把 128×128 或 `imgs.npz` 装进 RAM。

## 已核对

- `data/manifests/core50_mini.json`：`n_indexed_train_paths=119894`。共享测试 44972。`119894+44972=164866`，与 Table 2 图像总数一致。该数字是 **train+test**，不要把训练集条数单独写成 Table 2。mini 与 128×128 的差别是分辨率，不是这条计数。
- Avalanche `CORe50` 的 `test_stream` 长度为 1（共享测试集），不是 CIFAR 那种逐 experience 测试流。
- NC `run=0`、`object_lvl=True`：9 experiences，类集合不相交，首批 10 类、其后每批 5 类，共 50 对象类。评价采用 `shared_sliced_by_train_classes`（按该 experience 的训练类切共享测试）。
- 训练变换：`ToTensor` + `RandomHorizontalFlip` + ImageNet mean/std。这是 Avalanche CORe50 默认统计，**不是**论文写明的 mean/std；已是 32×32，不加 RandomCrop。

## NI / NIC

- NI：8 experiences，类集合重叠（新实例、同一组对象类）。不能按类切片冒充独立 `T_i`。采用 PLAN §5.3 的 `shared_test_temporal`：每个 k 只评一次共享测试得到 `a_k`，记账 `A[k,i]=a_k`。此时 `P_diag` 是历史 `a_i` 均值，`S_initial` 是相对历史时点的平均变化，**不是**不同经验知识的独立遗忘。主表必须同时给出 `a_k`（`experience_metrics.csv` 的 `shared_test_accuracy`）。
- NIC：论文 79 experiences。本仓库映射 `core50_nic` → Avalanche `nicv2_79`。这是 **重建**，尚未被作者配置证实；不得写成“已确认作者用的就是 NICv2-79”。类集合重叠，同样用 `shared_test_temporal`。

## 禁止

- 把 mini 训练条数写成复现了 Table 2 的 164866。
- 把 NI/NIC 的 `P_diag`/`S_initial` 与 CIFAR 或 NC 切片口径混报。
- 在预测端启用未声明的 task oracle。
