# A24 本机环境适配（Linux + 双 RTX 5090）

日期：2026-09-15。分类：适配本平台。不改写 A01 在原 WSL/5060 Ti 上已验证的版本选择。

## 决定

- Conda：使用共享 `/opt/miniconda3`（base 只读）。`orion` 环境与包缓存放在 `/home/zhuzetong/.conda/`。
- Python：3.11.16，与第一阶段起点一致。
- PyTorch：`torch==2.11.0+cu128`、`torchvision==0.26.0+cu128`。官方 cu128 索引上该组合为当前最新匹配对；`2.14.0` 只有 `cu130` 轮子。
- Avalanche：仍为 `avalanche-lib==0.6.0`，`--no-deps` 安装，另装 `wandb`，运行时 `WANDB_MODE=disabled`。
- GSS `mem_strength` 转 int 补丁保留。

## 理由

本机 NVIDIA 驱动 570.133.20，`nvidia-smi` 报 CUDA 12.8。CUDA 13 runtime 通常需要 580 系驱动。安装 `torch==2.14.0+cu130` 会在运行期与驱动不匹配。RTX 5090 需要 `sm_120`，cu128 轮子的 `arch_list` 含 `sm_120`。未改动系统驱动或 Toolkit。

## 验证

`conda run -n orion python -m orion_repro.envcheck`：前向/反向/参数更新通过；`arch_list` 含 `sm_120`。`pytest tests` 120 passed。产物：`reports/envcheck.json`、本机 `requirements.lock.txt` / `environment.lock.yml`。

## 影响

新阶段身份依赖当时本机锁文件，不能与 `docs/environments/wsl2_rtx5060ti/` 的 cu130 锁混为同一环境。5060 Ti 上的 `L_cal`、耗时和配额不自动沿用。

2026-09-16：此决定仍描述 5090 宿主如何建环境。按 [A26](A26.md) 该宿主上的 effectiveness_v3 执行证据已放弃；锁文件归档于 `docs/environments/linux_rtx5090/`。换机后另作环境决策，不要把 A24 的路径和 cu128 选择自动当成下一宿主配置。
