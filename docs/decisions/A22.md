# A22：Endless 开发划分

分类：platform_adaptation / unresolved。依据 PLAN §4.3、Avalanche 0.6.0 classification 数据结构及本地文件。

采用 `class_ordered_holdout_embargo_v2`：

- 数字 subsequence ID 确定 experience 顺序，核对 train/test 配对。
- 各 class 内按文件名数字 patch ID 排序；留出约 20% 的连续排名区段作为 val，split seed=17 确定起点。
- 留出区段两侧各最多 32 个 patch 排除，不用于训练或验证。窗口 32 是开发假设，需敏感性分析。
- 每个运行的 `split_manifest.json` 保存全部路径及 train/val/excluded 索引。未知命名、重复 ID、过短组均拒绝。

数字 patch ID 是排序代理，其与真实时间或源帧的对应关系未确认，不宣称完全消除时间相关性。Avalanche 文件系统列表本身不是可靠时间顺序。

当前配置名以 `_grouped_v2.yaml` 结尾，protocol_id 为 `development_endless_grouped_v2`。缺少显式分组策略的开发配置拒绝执行。正式实验应报告训练、验证及排除样本数，并保持各方法划分相同。
