# 可选 GEM+EWC 切换与非 ER 适配（A10）

论文 Table 1：ER 的 advanced 优化策略为 GEM 与 EWC。本仓库：

- ER 本体始终保留 `ReplayPlugin`（Naive + 显式插件，避免 `Replay()` 把 ReplayPlugin 接到用户插件之后、盖掉预取包装）。
- `optional_plugins: gem_ewc` 时用 `TogglePlugin` 包住 `GEMPlugin` 与 `EWCPlugin`。暂停模式为 **pause-compute-keep-state**：关掉时不再计算投影/Fisher 惩罚，但已有状态仍占内存。
- 等号行为跟随 Algorithm 1 的 `>`（A03）：`U == Thr` 保持 default。
- 从 default 首次切到 advanced 时，过去 experience 的 GEM 记忆为空；**不**从磁盘完整历史补回（PLAN §7.2）。`SparseGEMPlugin` 跳过缺失的 `memory_x[t]`，约束只作用于启用之后写入的经验。EWC 本身已跳过没有 Fisher 的 experience。
- Avalanche 0.6.0 的 `qpsolvers.solve_qp(..., solver="quadprog")` 在部分投影上返回 `None`。`SparseGEMPlugin.solve_quadprog` 此时保留当前梯度并计数 `qp_failures`，避免把实现错误当成科学失败。这不是原 GEM 论文求解器。
- 不得在 base=gem 上再叠一层 GEM。`optional_plugins=gem_ewc` 在 GEM/AGEM/GSS 上显式拒绝；GEM/AGEM/GSS 的 advanced 重建只允许 `optional_plugins=ewc`。
- URGE 现可作用于 GEM/AGEM/GSS：`new_batch` 写入 `train_mb_size`；GEM/AGEM 的 `patterns_per_experience = floor(replay_capacity / n_experiences)`（总槽位对齐 ER 的 MR，A10 映射，非论文公式）；GSS 的 `mem_size` 直接等于 replay_capacity。缩容截断已存样本，扩容不恢复被丢弃历史。
- T06 单元测试检查 GEM 投影后 `g_k·g' >= -γ`、AGEM 投影后 `g·g_ref >= 0`、GSS 满缓冲时调用官方 `get_batch_sim`、以及 off→on 跳过缺失 GEM 键。尚未用完整 `strategy.train` 对照官方 wrapper 的逐比特轨迹。
