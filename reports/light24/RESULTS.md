# light24_v1 结果报告

2026-09-14。范围与协议见 PLAN.md 与 docs/protocols/light24_v1.md；本文只汇总当前 study（light24_v1 身份）结果，不混入历史 71 次运行。主反馈口径为 paper_feedback（官方训练划分 + 已见官方测试反馈），是论文口径重建，非独立无测试反馈的泛化评价。

## 1. 执行概况

- 96 格全部执行：90 completed + 6 个有证据的资源失败（budget 128MiB 启动 CUDA OOM，两方法 × 3 seeds 全部失败并保留）。
- 累计正式训练执行 6725.6s（约 1.87h，runs/light24_progress.json；不含软件验证与本报告的 4 次复现性探针）。
- 主要比较均为 3 seeds；开发搜索只用开发 val 选择（两场景均选出 batch16/replay2000），正式评价与选择数据源分离。
- 数据表：means.csv（均值/样本标准差）、coverage.csv（逐格状态）、paired_diffs.csv（配对差）、run_artifacts.csv（资源与控制统计）、overhead.csv（分项耗时）、budget_summary.csv；图见 figures/。

## 3. 关键发现

**F1 自适应从未触发（C02 核心）。** 全部 12 个 core 自适应 run 中 URGE 峰值 0.006，远低于最低受试阈值 0.025（主值 0.05）。约束因子是延迟：每 experience 训练约 2–3s，远低于 L_th=30s，factor_l≈0.001 主导四因子乘积；显存占用 ~125MiB 远低于 M_max=4096MiB（factor_m 饱和 1.0）。控制器全部实际干预为：new_batch 16→15（首格一次）与 replay 容量每 experience −2 的温和衰减（200→182/184）；optimizer mode 从未切换（恒 default），插件状态恒空。提议=实际应用（无预算裁剪冲突）。

**F2 同初始资源时 Orion ≈ 静态 ER。** 由于 F1，完整 Orion 退化为“replay 容量缓慢衰减的 ER”。CIFAR100 差异全在噪声内；CORe50 出现方向一致的小幅 P↑S↓（dP +0.5~+3.3pp，dS −1.0~−4.8pp），方向与 replay 容量略降（−8%）一致，可解释为衰减的边际效应，非自适应扩容收益。

**F3 6 格小搜索选出的静态配置在两场景均优于两种自适应。** b16/r2000 以 −2~−12pp P 换 +12~+28pp S，(P+S)/2 由 0.51/0.54 升至 0.56/0.63。且 r2000 是搜索空间边界（最大受试值），未饱和，提示更公平的强静态基线还可更强。自动到达好配置的论文价值主张在本平台未实现（F1 使控制器无法离开初始资源区）。

**F4 batch/replay 权衡方向明确（C01）。** 1 epoch + lr0.01 下 batch256 使 P_diag 崩至 0.03–0.04（每 experience 步数过少）；replay 2000 稳定把 S 抬高 0.12–0.28。开发表见 means.csv L_search 行。插件维度本轮无证据（插件从未激活）。

**F5 显存预算：128MiB 不可行、256/512MiB 不约束（C06）。** 实测 PyTorch allocator 峰值占用 125–129MiB（两方法同量级），128MiB 配额启动即 OOM（6/6 全部失败，保留为真实资源结果；Orion 并未比静态更能规避启动 OOM）；256/512MiB 完成且质量与 core 一致（P/S 差 ≤1.5pp，噪声级）。allocator 配额只约束本进程 PyTorch 分配，不等于 host/全 GPU 硬限制；M_max 同步配额后 factor_m 仍为 1.0（占用 < 配额），内存压力未使控制器行为改变。

**F6 预取：语义完全等价、时间净变慢（C07）。** on/off 逐 seed dP=dS=0（访问计数完全一致：new 119894/replay 92336）；开启后 online_s +39~+56s（+31–44%），等待仅 0.2s（队列始终满），慢因是每批包装开销（7498 批 × ~7ms Python 队列管理）叠加于毫秒级 GPU 训练步。历史“预取变慢”在新 study 复现。仅覆盖静态轨迹，不代表动态策略下预取等价或有收益。

**F7 偏好与阈值敏感性均无行为差异（C05、sensitivity）。** latency/P-S 偏好改变 URGE 数值（latency 权重高使乘积更小），但所有 P/S/时间差异在 seed 噪声内；Thr0 ∈ {0.025, 0.05, 0.1} 三档结果噪声级一致（F1 的直接推论）。偏好表达需要控制器实际触发，本工作负载下不发生。

**F8 Endless 辅助验证（开发划分，不可混入官方测试主表）。** IC/IL/WC × ER/Orion × 3 seeds：P/S 差异 |dP|≤8pp、多数在噪声内且方向不一致；时间上 Orion 平均快 3.5–6.8s，但 IC 差距经 4 次重跑探针证伪为进程级主机计时方差（同一 er 配置 t0 在 5.9–9.0s 间波动；预热后 t1–t3 两方法一致），IL/WC 的 3–9% 差距幅度小，只能视为未定论倾向。Endless 使用 grouped_v2 开发划分与数字 patch ID 排序代理，不证明真实时间隔离。

**F9 系统开销分解（C08）。** 控制器决策 + 重配置合计 <0.01s/运行（<0.01% online），自适应控制的直接成本可忽略；评价耗时占 online 的 16%（CIFAR100）/39%（CORe50，paper_feedback 协议的固有成本）；进程 RSS 峰值 ~2.0GB，swap 峰值 60–93MiB（轻微换页已记录，未观察到对训练延迟的系统性影响）。分项数据见 overhead.csv、run_artifacts.csv。

## 4. C01–C08 限定结论

| 命题 | 判定 | 依据与边界 |
|---|---|---|
| C01 参数/插件权衡 | 部分支持 | batch/replay 方向证据强（F4）；插件维度未激活无证据；每场景仅 6 格、r2000 边界未饱和 |
| C02 自适应机制有效 | 不支持（本范围） | F1/F2：URGE 从未触发，完整 Orion ≈ 初始资源静态 ER；非证明机制在受限设备上无效，本平台延迟/显存均远离 sigmoid 激活区 |
| C03 跨场景方法权衡 | 部分支持 | F2/F3 在两场景方向一致；CORe50 有小幅 P↑S↓ 衰减效应；不外推到五基准全集 |
| C04 多算法普适性 | 未验证（范围外） | 本轮不扩展；历史 ER/GEM/AGEM/GSS 证据与 GSS 崩塌保留为背景 |
| C05 用户偏好 | 不支持（本范围） | F7：权重实现生效但无行为/指标差异；需要触发条件的研究 |
| C06 内存预算 | 部分支持 | F5：配额机制真实起作用并产生真实失败边界（128MiB OOM）；但 Orion 未展现预算下的适应优势，且 allocator ≠ host/全 GPU 硬限制 |
| C07 统一预取 | 部分支持（语义等价）/ 不支持（收益） | F6：等价性证明严格（逐 seed 全等）；本平台为净减速，原因已定位 |
| C08 系统开销 | 支持（限定） | F9：控制器开销可忽略；评价与（若开启的）预取包装才是主要时间项；分项口径已给出 |

本轮为代表性子命题验证，不覆盖原论文全部实验（MAX-A 全矩阵、8×42 Oracle、非 ER 组合、Endless 144 格、Jetson 能耗与机器人闭环均在范围外）。

## 5. 局限

- paper_feedback 含官方测试反馈，是论文口径重建而非独立泛化评价；开发选择未使用这些结果。
- URGE 数值依赖 L_th=30s、M_max=4096MiB 等未经作者确认的绝对阈值（对齐记录见 docs/alignment.csv）；本平台上这些阈值使触发条件系统性不可达。
- 预算实验的可行下界（~129MiB）高于 128MiB 配额，未能构造“配额可满足但内存紧张”的受压区；未验证控制器在真正内存压力下的行为。
- Endless 为开发划分 + 排序代理；主机计时方差（F8）要求小加速结论必须配对并做重跑探针。
- 单 GPU 单进程串行；WSL RAM 上限 6GB 下 RSS ~2GB、轻微换页已记录。

## 6. 对后续研究的启发

1. **阈值平台化**：四因子乘积要求四类压力同时存在才触发；绝对阈值（L_th=30s）跨平台不可迁移。研究按平台分位数/相对目标归一化的触发条件（METHODS 已列 normalized_variant 候选），并在受限平台上重验。
2. **压力区实验设计**：要检验 Orion 的核心主张，需构造“占用贴近配额、延迟贴近阈值”的工作负载（更大模型/更慢存储），或直接在边缘设备上测；本桌面 GPU 平台天然处于所有 sigmoid 的饱和安全区。
3. **自适应 vs 小搜索**：在触发不可达时，控制器等价于初始静态配置 + 固定衰减；一个 6 格离线搜索即可显著超越。值得研究“控制器触发前的初始化策略”（如用离线 profile 选 MB0/MR0）能否弥补。
4. **预取收益条件**：预取只在数据供给慢于计算时有价值（慢存储/重增强/多 worker）；内存张量 + 毫秒级步长下纯增开销。平台保真度应进入预取结论的适用条件。
5. **计时方法学**：进程级冷启动方差可达 40%+（F8），小加速结论必须逐 seed 配对 + 同配置重跑探针；报告在线时间时应分离评价与学习段。
