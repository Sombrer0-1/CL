# G5 裁决：已准入正式块与未建立缺口

更新：2026-09-30 10:40（UTC+8）。对照设计契约 §4.4 与 §6。这是阶段 4 已准入证据的裁决，不是「1320 格全部完成」。

已准入并跑完的正式块只有 `g4-h4-mem8g`（48 格）。数字见 [G4_H4](G4_H4.md)。静态宽/中/紧在 64/32/16/8 GiB 上都未建立。8G 不是 tight。其余设计名额留在分母里，记覆盖缺口，不记成负效果，也不删掉。

## 研究决策

现有正式证据不支持把 Orion 当作后续研究要整体借鉴的方法。

依据限于已准入的 H4 共运行压力：NC 上 O-recon 对动态 S* 六条 seed 的可塑性都更差（约 0.20–0.27），稳定性没有稳定更好，在线时间更长；NIC 上完整 O-recon 六格都被同一 2.5 GiB 持有下的 systemd oom-kill 终止，而 S0、S*、BR-adapt 都完成。这是限定场景里的负结果加资源失败，不是对未跑块的无效证明。

静态压力、跨算法主比较、Endless 官方协议、偏好、预取净收益、插件物理块和敏感性都未验证。科学上记未验证。研究上不再为这些缺口追加参数搜索、换模型或改主方法。用户若要另开问题，需要明确新指示。本轮不发射 `FREEZE.json` 以外的 `kind=train`。

## 限制

- 主比较只覆盖 CORe50 NC/NIC、ResNet-20、32×32、`mem=8G` 加 2.5 GiB 后台持有。
- 动态 S* 是该序列上的开发选择（NC low→high→low 为 b64/r2000，其余三条为 b16/r2000），不是 64 GiB CIFAR-100 的静态 S*。
- Git HEAD 仍是 v3 `b59b4c4`。v4 身份在冻结快照 `0311c783…`，不在这次提交的 git 哈希里自动等价。
- `runs/` 不进 git。推送不等于证据备份。
- 硬整机不可恢复崩溃按设计没有主动撞。oom-kill 是训练进程被杀、机器仍在，健康检查为 ok。
